# Manual checklist: gallery.html

- **Test with a real screen reader (NVDA or JAWS on Windows, VoiceOver on macOS/iOS).** — No automated tool, and no simulator, reproduces real AT behaviour — NVDA, JAWS and VoiceOver diverge from each other and from the specification.
- **Tab through the page and confirm the focus order is logical, not merely present.** — a11y-loop can see that focus moves and where it goes, but whether the sequence makes sense for this content is a human judgment.
- **Complete the page’s main task using only the keyboard.** — Automated checks probe individual controls; they do not know what the user is trying to accomplish.
- **Confirm the alt text on 6 images is accurate and useful, and that decorative images use alt="" rather than a description.** — Automation can only see whether alt text exists. alt="decorative image" passes every automated rule and is worse than alt="". If any alt text was generated by an AI, treat it as a draft that a human must confirm.
- **Read each link text out of context and confirm the destination is still clear.** — SC 2.4.4 permits vague link text when the surrounding context supplies the purpose — whether it does is a judgment call.
- **Confirm the heading structure describes the content hierarchy, not the visual sizes.** — Automation can detect skipped levels but not whether the outline reflects the actual structure of the page.
- **Review the 12 ARIA attributes on this page: is each one appropriate, or merely valid?** — Pages using ARIA average more accessibility errors than pages without it (WebAIM Million 2026: 59.1 vs 42.0). A role is a promise — role="button" commits to the full keyboard behaviour of a button. No ARIA is better than bad ARIA.
- **Confirm colour is never the only way information is conveyed.** — SC 1.4.1 is one of the criteria no tool can test: recognising that "the required fields are in red" needs comprehension of the content.
- **Check the contrast of hover and focus states.** — No engine checks state contrast unless the state is driven and re-scanned. Use --interact to add hover and focus states to the audit.
